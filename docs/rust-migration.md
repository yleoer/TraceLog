# Rust / Tauri 迁移记录

TraceLog 已从 Go/Wails 迁移至 Rust + Tauri 2，保留 Vue 3 + Naive UI 工作界面与 SQLite 数据。项目按个人单机使用维护，优先简单、直接的实现。

## 已完成的迁移

| 阶段 | 交付 |
| --- | --- |
| 1 | Tauri 入口、用户级 NSIS 安装和官方签名更新插件 |
| 2 | Rust 配置、数据层、旧数据库兼容及首次迁移备份 |
| 3 | 本地业务、日周视图、甘特、搜索、导出和 Vue 原生 IPC |
| 4 | Jira、Tempo、AI、图片、剪贴板和外部链接 |
| 5 | Rust 构建发布流程、Wails 首次迁入说明及旧实现清理 |

迁移期间完成过实际安装、连续签名升级和异常升级验证，详细过程保留在 Git 历史中。

## 保留的基础机制

- 数据目录仍为 `%APPDATA%/TraceLog`，兼容原有数据库、设置和图片。
- 首次迁移先做一致性备份，结构和搜索索引转换在事务内完成，重复启动不会重复转换。
- 前端统一通过 `frontend/src/api/client.ts` 调用原生能力，业务不依赖本地 HTTP 服务。
- 更新继续使用 Tauri 官方插件、HTTPS 和签名校验；CI 使用原有签名私钥。
- 设置原子保存，空凭据保留；异步生成结果只更新相关业务字段。
- 修复后的日期逻辑继续保留：首周包含历史完成时间，日周统计正确处理毫秒和时区偏移。

## 按个人单机使用精简

移除通用设置字段合并、并发冲突检测、额外任务锁、全局 IPC 等待队列，以及测试专用功能开关、IPC 和前端入口。删除多版本安装验收脚本、回环更新服务和独立验签工具。

测试保留核心业务正常流程与已经修复的日期问题，删除并发竞争、故障注入和攻击输入矩阵。CI 日常只做格式、快速业务测试、Clippy 与前端构建，手动运行或版本标签才打包，不再重复构建多个测试版本。

常规改动不默认生成正式安装器。只有直接修改安装或升级机制时，才按实际需要做针对性的手工确认。

发布仍需确认变更清单，创建标签前准备 `release-notes/<tag>.md`。首次从旧 Wails 安装迁入时按 README 备份和安装即可。
